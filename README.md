# VIMON10 - Система видеомониторинга для камер

## Общее описание

**VIMON10** - это FPGA-система видеомониторинга для камер MVK3, разработанная компанией Protei. Проект реализован на языке VHDL для чипа Gowin GW2AR-18C и предназначен для работы в качестве видоискателя для камер производства Протей с возможностями управления и мониторинга.

Система обеспечивает прием видеопотока по Ethernet, обработку и отображение на LCD дисплее с разрешением 1280x800, управление камерой через VISCA протокол, а также мониторинг состояния системы и окружающей среды.

## Технические характеристики

- **Целевая платформа**: Gowin GW2AR-18C FPGA
- **Версия железа**: 9 (HW VIMON10a)
- **Версия ПО**: 3.2.3 (vimon10_009-003-002-003.fs)
- **Разрешение видео**: 
  - Вход: 1920x1080 (Full HD)
  - Выход: 1280x800 (WXGA)
  - Активная область изображения: 960x540
- **Частота обновления**: 60 FPS
- **Формат видео**: YCbCr 4:2:0 (вход) → YCbCr 4:4:4 → RGB (выход)
- **Интерфейсы**: 
  - Ethernet 1 Gbps (прием видео, передача команд)
  - LVDS (вывод на дисплей)
  - I2C (датчик BME280)
  - MDIO (управление PHY YT8531)
- **Дисплей**: Tianma TM080TDHG01-40, 8 дюймов, LVDS интерфейс

## Архитектура системы

### Основные компоненты

#### 1. Центральный модуль (vimon10.vhd)
- Объединяет все подсистемы
- Управляет тактовыми сигналами через PLL
- Координирует работу всех модулей
- Обрабатывает сигналы сброса и синхронизации

#### 2. Видеосистема

**ethrx_module** - Прием видео по Ethernet
- Принимает видеопоток в формате YCbCr 4:2:0
- Разрешение: 1920x1080
- Обработка Ethernet пакетов с CRC32 проверкой
- Буферизация в видеопамяти
- Обработка UDP пакетов
- Проверка целостности данных
- Управление потоком данных
- Обработка ошибок передачи

**gpu** - Обработка видеопотока
- Управление памятью SDRAM
- Двойная буферизация для плавного воспроизведения (ping-pong)
- Обработка ошибок синхронизации
- Контроль последовательности кадров
- Масштабирование видео (1920x1080 → 960x540)
- Управление адресацией видеопамяти
- Обработка запросов на чтение/запись
- Контроль таймаутов доступа к памяти

**lcd_module** - Вывод на дисплей
- Разрешение: 1280x800 @ 60 Hz
- Интерфейс LVDS для подключения дисплея (4 канала данных + тактовый)
- Управление подсветкой через PWM (частота ~18.8 кГц, синхронизировано с кадрами)
- Конвертация YCC420 → YCC444 → RGB (ITU-R BT.601)
- Генерация синхросигналов (HSYNC, VSYNC)
- Последовательность инициализации дисплея с задержками
- Двойная буферизация для плавного воспроизведения
- Обработка состояния "нет сигнала" (шахматный паттерн с анимацией)
- Наложение графики и текста поверх видео
- Управление питанием дисплея (LCD_EN_VDD)
- Управление сбросом дисплея (LCD_RST)
- Управление разрешением работы (LCD_EN)

**grafics_ctr** - Графические элементы
- Наложение текста и графики поверх видео
- Отображение статусной информации
- Генерация тестовых паттернов
- Управление приоритетом отображения (графика > границы > видео)
- Работа с текстовой картой (txt_map)
- Синхронизация с видеосигналом

#### 3. Сетевой интерфейс

**ethtx_module** - Передача команд
- Отправка команд управления камерой
- UDP пакеты с VISCA командами
- Управление зумом камеры

**YT8531_module** - Управление PHY
- Интерфейс MDIO для управления PHY чипом YT8531
- Фиксированная скорость: 1 Gbps (настройка через предзаписанные регистры в памяти)
- Проверка состояния соединения (чтение регистров статуса связи)
- Вывод сигнала link[1:0] - статус связи для двух портов
- Использование предзаписанной памяти конфигурации (YT8531_mdiomem)

**cmd_module** - Обработка команд
- Обработка нажатий кнопок (KEY[3:0])
- Генерация VISCA команд для зума
- Управление яркостью дисплея (KEY[3-5])
- Фильтрация дребезга контактов (hardware filter)
- Формирование UDP пакетов для передачи команд
- Буферизация команд в памяти
- Таймеры для периодических операций (10 мс, 50 мс, 500 мс)

#### 4. Сенсоры и мониторинг

**bme280_module** - Датчик окружающей среды
- Температура, давление, влажность
- Интерфейс I2C
- Компенсация и калибровка данных

**stat_module** - Сбор статистики
- Отображение всех параметров системы
- Форматирование данных для экрана
- Конвертация числовых значений в текст
- Формирование текстовой карты для наложения на видео
- Отображение версий ПО и железа
- Статистика ошибок по типам
- Параметры камеры (зум, звук, питание, температура)
- Состояние связи Ethernet

## Поток данных

### Видеопоток

```
Ethernet (1920x1080 YCbCr 4:2:0)
    ↓
ethrx_module (прием UDP пакетов, проверка CRC32)
    ↓
video_mem (двухпортовая память, двойная буферизация)
    ↓
gpu (управление SDRAM, масштабирование, обработка ошибок)
    ↓
SDRAM (внешняя память для буферизации кадров)
    ↓
lcd_module (чтение из памяти, конвертация цветов)
    ↓
YCbCr 4:2:0 → YCbCr 4:4:4 → RGB (ITU-R BT.601)
    ↓
LVDS сериализатор (225 MHz)
    ↓
Дисплей (1280x800 RGB)
```

**Особенности видеопотока:**
- Формат входного видео: YCbCr 4:2:0 (хроминенция с субдискретизацией 2:1)
- Масштабирование: 1920x1080 → 960x540 (активная область) с отображением на 1280x800
- Двойная буферизация: ping-pong буферы для плавного воспроизведения
- Обработка ошибок: контроль последовательности кадров, проверка CRC32

### Команды управления

```
Кнопки KEY[3:0]
    ↓
cmd_module (фильтрация дребезга, обработка нажатий)
    ↓
Генерация VISCA команд (зум, статус)
    ↓
CMDtxmem (буферизация команд)
    ↓
ethtx_module (формирование UDP пакетов)
    ↓
Ethernet (передача команд камере)
```

**Поддерживаемые команды:**
- Управление зумом (увеличение/уменьшение/стоп)
- Запрос статуса камеры
- Управление яркостью дисплея (локально)

### Данные сенсоров

```
BME280 (I2C интерфейс)
    ↓
bme280_module (чтение данных, компенсация)
    ↓
stat_module (форматирование, конвертация в текст)
    ↓
txt_map (память текстовой карты)
    ↓
grafics_ctr (наложение текста на видео)
    ↓
lcd_module (отображение на дисплее)
```

**Отображаемые данные:**
- Температура, давление, влажность (BME280)
- Версия ПО и железа
- Статус связи с камерой
- Параметры камеры (зум, звук, питание)
- Уровень яркости дисплея
- Статистика ошибок системы

## Тактовые домены

Система использует несколько тактовых доменов:

- **CLK25M** (25 MHz) - опорная частота
- **ethtx_clock** (125 MHz) - передача Ethernet
- **eth0rx_clock** (125 MHz) - прием Ethernet  
- **gpu_clk** (125 MHz) - обработка видео
- **sdram_clk** (125 MHz) - работа с SDRAM
- **lcd_sclk** (225 MHz) - сериализация LVDS
- **lcd_pclk** (64.286 MHz) - пиксельная частота LCD
- **int_clk** (18.367 MHz) - внутренние процессы

## Интерфейсы

### Внешние порты
- **Ethernet**: ETH0_RXD/TXD, ETH0_RXCLK/TXCLK, ETH0_RXCTL/TXCTL
- **LCD**: LVDS_A_OUT_CLK, LVDS_A_OUTP[3:0], LCD_EN_VDD, LCD_PWM, LCD_EN_LED, LCD_RST
- **SDRAM**: O_sdram_clk, O_sdram_cke, O_sdram_cs_n, O_sdram_cas_n, O_sdram_ras_n, O_sdram_wen_n
- **I2C**: Sensor_SCL, Sensor_SDA (датчик BME280)
- **MDIO**: ETH_MDC, ETH_MDIO (управление PHY)
- **Кнопки**: KEY[3:0] (управление)
- **Индикаторы**: LED_GREEN, LED_BLUE, LED_RED

### Внутренние интерфейсы
- **Видеопамять**: Двухпортовая память для буферизации
- **SDRAM**: Интерфейс для внешней памяти
- **Командная память**: Буферизация команд управления

## Управление яркостью подсветки

Система поддерживает плавное управление яркостью дисплея с широким диапазоном регулировки.

### Параметры яркости

- **Диапазон**: 0-128 уровней (технический), рабочая область 10-100%
- **Минимальная рабочая яркость**: 10% (BACKLIGHT_MIN = 0, но минимальная рабочая = 10%)
- **Яркость по умолчанию**: 63% (BACKLIGHT_DEFAULT = 63)
- **Максимальная яркость**: 100% (BACKLIGHT_MAX = 128)
- **Маржа PWM**: 15 уровней (BACKLIGHT_MARGIN_MIN = 15) - используется для предотвращения полного гашения подсветки

### Управление кнопками

- **KEY(3)**: Увеличение яркости (+1% каждые 10 мс при удержании)
- **KEY(4)**: Уменьшение яркости (-1% каждые 10 мс при удержании)
- **KEY(5)**: Сброс к значению по умолчанию (63%, мгновенно)

### Реализация PWM

- **Частота PWM**: ~18.8 кГц (27000 циклов, 18844KHz при -53db)
- **Синхронизация**: PWM синхронизирован с частотой кадров (60 FPS)
- **Разрешение**: 99 шагов за период кадра
- **Механизм**: 
  - PWM сигнал HIGH в начале каждого кадра
  - Переключение в LOW при достижении порога (BACKLIGHT_MARGIN_MIN + backlight)
  - Инверсия сигнала перед подачей на дисплей (LCD_PWM = not int_LCD_PWM)
- **Защита**: Использование маржи предотвращает полное гашение подсветки при минимальных значениях

### Последовательность включения дисплея

1. **Кадр 0**: Все сигналы выключены (LCD_EN_VDD='0', LCD_RST='0', LCD_EN='0', PWM_ena='0')
2. **Кадр 1**: Включение питания (LCD_EN_VDD='1'), установка сброса (LCD_RST='1')
3. **Кадр 10**: Снятие сброса (LCD_RST='0') - задержка 9 кадров (~150 мс)
4. **Кадр 15**: Разрешение работы дисплея (LCD_EN='1') - задержка 5 кадров (~83 мс)
5. **Кадр 30**: Разрешение PWM подсветки (PWM_ena='1') - задержка 15 кадров (~250 мс)

Общее время инициализации: ~500 мс (30 кадров при 60 FPS)

## Обработка ошибок

Система отслеживает 9 типов ошибок с индивидуальными счетчиками (0-255):

1. **Ошибки CRC32 в видеопакетах** - несоответствие контрольной суммы в принятых пакетах
2. **Ошибки последовательности кадров** - нарушение последовательности номеров кадров
3. **Ошибки синхронизации видео** - проблемы с синхронизацией видеопотока
4. **Таймауты чтения SDRAM** - превышение времени ожидания доступа к памяти
5. **Ошибки подписи пакетов** - неверная сигнатура в заголовках пакетов
6. **Ошибки буферизации** - проблемы с управлением видеобуферами
7. **Ошибки связи с камерой** - проблемы с Ethernet соединением
8. **Ошибки чтения сенсоров** - проблемы с получением данных от BME280
9. **Ошибки обработки команд** - ошибки при формировании или передаче команд

Все ошибки отображаются на экране через модуль статистики и могут использоваться для диагностики системы.

## Особенности реализации

### 1. Многочастотная архитектура

Система использует несколько PLL для генерации различных тактовых частот:
- Опорная частота 25 MHz умножается/делится для получения требуемых частот
- Каждый домен имеет свою частоту, оптимизированную для конкретной задачи
- Использование синхронизаторов для безопасной передачи данных между доменами

### 2. Двойная буферизация (Ping-Pong)

- Два независимых буфера для видеоданных
- Пока один буфер отображается, другой заполняется новыми данными
- Переключение буферов синхронизировано с вертикальной синхронизацией
- Обеспечивает плавное воспроизведение без разрывов кадров

### 3. Синхронизация тактовых доменов

- Использование специализированных модулей синхронизации (Sync, resync)
- Защита от метастабильности при передаче сигналов между доменами
- Раздельные сигналы сброса для каждого домена с правильной последовательностью

### 4. Обработка ошибок

Система отслеживает 9 типов ошибок:
- Ошибки CRC32 в видеопакетах
- Ошибки последовательности кадров
- Ошибки синхронизации видео
- Таймауты чтения SDRAM
- Ошибки подписи пакетов
- Ошибки буферизации
- Ошибки связи с камерой
- Ошибки чтения сенсоров
- Ошибки обработки команд

Каждый тип ошибки имеет счетчик (0-255) для статистики.

### 5. Адаптивное управление

- Динамическое управление яркостью с плавным изменением
- Автоматическая обработка состояния "нет сигнала"
- Адаптивная обработка различных форматов видео
- Мониторинг состояния всех подсистем в реальном времени

### 6. Конвертация цветового пространства

- **YCbCr 4:2:0 → YCbCr 4:4:4**: Увеличение разрешения хроминенции (upsampling)
- **YCbCr 4:4:4 → RGB**: Конвертация по стандарту ITU-R BT.601
- Конвейерная обработка для минимизации задержек
- Обработка 4 пикселей одновременно (96-битные слова из памяти)

### 7. Управление памятью

- **Видеопамять**: Двухпортовая память 8192x32 бит (двойной буфер)
- **SDRAM**: Внешняя память для буферизации кадров
- **Командная память**: Буферизация команд управления камерой
- Эффективное использование пропускной способности памяти
